# Runbook Go-Live SIMANTAP — 31 Agustus 2026

Dokumen ini ditujukan untuk go-live awal dari Windows/XAMPP. Jangan membuka
XAMPP langsung ke internet. Bila akses hanya dibutuhkan di kantor, gunakan
Apache pada PC yang selalu menyala di LAN internal sambil menyiapkan server
produksi permanen bersama pengelola TI.

Pilihan tanpa hosting hanya aman untuk penggunaan sementara berikut:

| Kebutuhan Senin | Keputusan |
| --- | --- |
| Dipakai pada PC server saja | XAMPP lokal dapat digunakan |
| Dipakai beberapa PC pada jaringan kantor yang sama | XAMPP melalui LAN internal dapat digunakan |
| Dipakai dari rumah, jaringan lain, atau internet | Belum siap; perlu server terkelola dan HTTPS |

## 1. Keputusan sebelum mulai

- Seluruh `vehicle_loans` yang ada adalah data UAT dan boleh dihapus.
- Seluruh pemeliharaan yang ada juga merupakan data UAT dan ikut dihapus dengan
  opsi eksplisit `--include-all-maintenance`.
- Master kendaraan, master aset perangkat, pengguna, persediaan, dan transaksi
  modul lain harus dipertahankan.
- Nomor dokumen `LOAN` dan `MTC` dimulai kembali dari `0001`; auto-increment
  database tidak perlu direset.
- Jangan menjalankan pembersihan tanpa backup MySQL dan folder file private.

## 2. Validasi kode sebelum pembersihan

Jalankan dari PowerShell:

```powershell
cd C:\xampp\htdocs\simantap

git status --short --branch
git pull --ff-only origin feature/fondasi-aplikasi

.\vendor\bin\pint --test
php artisan test --filter=VehicleLoanUatCleanupTest
php artisan test
npm run build
```

Semua perintah harus lulus. Test menggunakan SQLite `:memory:` dan tidak
membersihkan database MySQL aplikasi.

Jika masih memerlukan satu uji manual terakhir melalui browser, lakukan pada
tahap ini. Jangan membuat transaksi uji baru setelah pembersihan one-time.

## 3. Minggu: backup final sebelum pembersihan

Tutup browser pengguna dan pastikan tidak ada orang yang sedang bertransaksi.
Sesuaikan nama database dan user dengan `.env`.

```powershell
cd C:\xampp\htdocs\simantap

$stamp = Get-Date -Format "yyyyMMdd-HHmmss"
$backupDir = "C:\simantap-backups\$stamp"
New-Item -ItemType Directory -Path $backupDir -Force | Out-Null

$databaseBackup = Join-Path $backupDir "simantap-before-uat-cleanup.sql"
& "C:\xampp\mysql\bin\mysqldump.exe" `
    --host=127.0.0.1 `
    --user=simantap_app `
    --password `
    --single-transaction `
    --routines `
    --triggers `
    --result-file="$databaseBackup" `
    simantap

if ($LASTEXITCODE -ne 0) {
    throw "Backup database gagal. Pembersihan dibatalkan."
}

$privateBackup = Join-Path $backupDir "storage-private-before-uat-cleanup.zip"
Compress-Archive `
    -Path ".\storage\app\private" `
    -DestinationPath $privateBackup `
    -CompressionLevel Optimal `
    -Force

Copy-Item ".env" (Join-Path $backupDir "env.production.backup")
Get-ChildItem $backupDir | Select-Object Name, Length, LastWriteTime
Get-FileHash $databaseBackup, $privateBackup -Algorithm SHA256
```

Simpan folder backup di media/lokasi yang hanya dapat diakses administrator.
File `.env` berisi rahasia dan tidak boleh dikirim melalui chat atau masuk Git.

## 4. Minggu: simulasi dan pembersihan UAT

Turunkan aplikasi, lalu jalankan simulasi. Periksa jumlah peminjaman,
pemeliharaan, file, perubahan kendaraan, dan perubahan aset perangkat.

```powershell
$maintenanceSecret = "simantap-" + [guid]::NewGuid().ToString("N")
php artisan down --secret="$maintenanceSecret"

php artisan simantap:cleanup-vehicle-loans `
    --include-all-maintenance | Tee-Object `
    -FilePath (Join-Path $backupDir "cleanup-dry-run.txt")
```

Jika hasil simulasi sesuai, jalankan eksekusi permanen:

```powershell
php artisan simantap:cleanup-vehicle-loans `
    --execute `
    --include-all-maintenance `
    --database-backup="$databaseBackup" `
    --private-files-backup="$privateBackup" `
    --confirmation="HAPUS-SEMUA-PEMINJAMAN-UAT"
```

Secara default, odometer kendaraan dikembalikan ke nilai checkout paling awal
yang ditemukan pada data UAT. Jika angka odometer master saat ini sudah
diganti berdasarkan pembacaan fisik resmi dan harus dipertahankan, ulangi
simulasi dengan `--keep-odometers`, periksa kolom target, lalu tambahkan opsi
yang sama pada perintah eksekusi.

Perintah akan menolak eksekusi jika aplikasi belum dalam maintenance mode,
kedua file backup tidak ada/kosong, atau frasa konfirmasi tidak persis sama.
Path, ukuran, dan checksum SHA-256 backup dicatat pada manifest hasil di
`storage/app/private/cleanup-manifests`.

Command ini hanya dapat berhasil satu kali. Setelah audit
`uat_vehicle_loan_cleanup_completed` tercatat, eksekusi berikutnya akan
ditolak agar command tidak dapat menghapus peminjaman operasional setelah
go-live.

Validasi ulang:

```powershell
php artisan simantap:cleanup-vehicle-loans --include-all-maintenance
php artisan test --filter=VehicleLoanUatCleanupTest
php artisan test --filter=VehicleLoanTest
php artisan test --filter=VehicleReturnTest
```

Simulasi kedua harus menunjukkan nol peminjaman. Jangan jalankan `php artisan
up` jika manifest melaporkan kegagalan penghapusan file.

## 5. Konfigurasi produksi lokal/LAN

Nilai minimum `.env`:

```dotenv
APP_ENV=production
APP_DEBUG=false
APP_URL=http://IP-PC-SERVER:8080
APP_TIMEZONE=UTC
SIMANTAP_DISPLAY_TIMEZONE=Asia/Jakarta

LOG_LEVEL=warning
SESSION_DRIVER=database
SESSION_ENCRYPT=true
QUEUE_CONNECTION=database
CACHE_STORE=database
SIMANTAP_UPLOAD_DISK=local
```

Pastikan `APP_KEY` yang sekarang tidak diubah setelah data terenkripsi mulai
dipakai. Ganti kredensial administrator bawaan dan password database dengan
nilai kuat. Jangan menyimpan rahasia tersebut di Git.

Laravel harus disajikan dari folder `public`, bukan root repository. Contoh
VirtualHost XAMPP pada port internal khusus:

```apache
Listen 8080

<VirtualHost *:8080>
    ServerName simantap.internal
    DocumentRoot "C:/xampp/htdocs/simantap/public"

    <Directory "C:/xampp/htdocs/simantap/public">
        Options -Indexes +FollowSymLinks
        AllowOverride All
        Require ip 127.0.0.1 192.168.1.0/24
    </Directory>

    ErrorLog "logs/simantap-error.log"
    CustomLog "logs/simantap-access.log" combined
</VirtualHost>
```

Ganti `192.168.1.0/24` dengan subnet kantor yang benar. Buat DHCP reservation
atau IP statis untuk PC server. Aturan Windows Firewall hanya boleh membuka
port 8080 pada profil Private dan subnet kantor. MySQL tidak perlu dibuka ke
jaringan karena Apache dan MySQL berada pada PC yang sama.

Cari alamat IPv4 aktif dan pastikan profil jaringan adalah `Private`:

```powershell
Get-NetIPConfiguration |
    Where-Object { $_.IPv4DefaultGateway -ne $null } |
    Select-Object InterfaceAlias, IPv4Address, IPv4DefaultGateway

Get-NetConnectionProfile |
    Select-Object InterfaceAlias, NetworkCategory
```

Setelah subnet pada VirtualHost benar, buka PowerShell sebagai Administrator
dan buat aturan firewall terbatas ke jaringan lokal:

```powershell
New-NetFirewallRule `
    -DisplayName "SIMANTAP LAN 8080" `
    -Direction Inbound `
    -Action Allow `
    -Protocol TCP `
    -LocalPort 8080 `
    -Profile Private `
    -RemoteAddress LocalSubnet
```

Pastikan baris berikut aktif pada
`C:\xampp\apache\conf\httpd.conf`:

```apache
Include conf/extra/httpd-vhosts.conf
```

Simpan konfigurasi VirtualHost pada
`C:\xampp\apache\conf\extra\httpd-vhosts.conf`, lalu periksa sebelum restart
Apache:

```powershell
& "C:\xampp\apache\bin\httpd.exe" -t
netstat -ano | findstr :8080
```

Hasil `httpd.exe -t` wajib `Syntax OK`. Sesudah Apache direstart, uji dari PC
server dan satu PC lain pada LAN:

```text
http://IP-PC-SERVER:8080/up
http://IP-PC-SERVER:8080/login
```

Jangan gunakan `php artisan serve` sebagai server go-live dan jangan membuat
port-forwarding router. HTTP LAN hanya layak sebagai solusi sementara pada
jaringan kantor tepercaya; akses internet atau Wi-Fi yang tidak tepercaya
wajib memakai server yang dikelola dan HTTPS valid.

Setelah Apache dikonfigurasi:

```powershell
php artisan optimize:clear
php artisan migrate --force
php artisan optimize
php artisan about --only=environment
php artisan route:list
```

Laravel merekomendasikan cache konfigurasi, event, route, dan view saat
deployment; `php artisan optimize` menjalankan cache deployment tersebut.
Referensi: <https://laravel.com/docs/13.x/deployment> dan dokumentasi
VirtualHost Apache: <https://httpd.apache.org/docs/2.4/vhosts/examples.html>.

## 6. Scheduler Windows

Notifikasi jatuh tempo dan stok minimum bergantung pada Laravel Scheduler.
Buat Windows Task Scheduler yang berjalan setiap satu menit:

```text
Program/script:
C:\xampp\php\php.exe

Arguments:
C:\xampp\htdocs\simantap\artisan schedule:run

Start in:
C:\xampp\htdocs\simantap
```

Jalankan task sekali secara manual dan pastikan hasilnya sukses. Akun Windows
yang menjalankan Apache/scheduler harus memiliki akses baca-tulis ke
`storage` dan `bootstrap/cache`.

## 7. Checklist Minggu malam dan Senin pagi

### Minggu malam

- Apache dan MySQL otomatis berjalan setelah PC restart.
- Halaman `/up` merespons sukses dari PC pengguna lain di LAN.
- Login administrator berhasil dan password awal sudah diganti.
- Daftar peminjaman kosong.
- Kendaraan UAT kembali `Tersedia` dan odometernya sesuai baseline checkout.
- Pemeliharaan manual serta modul persediaan tetap ada.
- Unduh satu PDF dan periksa QR/verifikasi dokumen.
- Simulasikan restart PC server lalu ulangi login.

### Senin pagi sebelum pengguna masuk

```powershell
cd C:\xampp\htdocs\simantap
php artisan migrate:status
php artisan about --only=environment
php artisan schedule:list
php artisan up
```

Pantau `storage/logs/laravel.log`, log Apache, ruang disk, dan halaman audit
selama hari pertama. Bila terjadi masalah data, turunkan aplikasi dan gunakan
backup sebelum pembersihan; jangan memperbaiki langsung dengan query acak.

## 8. Jalur pemulihan bila validasi gagal

Jangan naikkan aplikasi jika data hasil pembersihan tidak sesuai. Biarkan
maintenance mode aktif, simpan manifest cleanup, lalu pulihkan dump SQL melalui
menu **Import** phpMyAdmin ke database `simantap`.

Untuk file private, pindahkan folder hasil gagal ke lokasi karantina dan
ekstrak arsip backup ke `storage/app`:

```powershell
$failedPrivate = ".\storage\app\private-failed-$(Get-Date -Format 'yyyyMMdd-HHmmss')"
Move-Item ".\storage\app\private" $failedPrivate
Expand-Archive `
    -Path $privateBackup `
    -DestinationPath ".\storage\app" `
    -Force
```

Setelah pemulihan, jalankan `php artisan optimize:clear`, periksa data melalui
aplikasi, dan baru jalankan `php artisan up` jika hasilnya benar.
